# 本地飞书文档 · 飞书同步（Obsidian 可选扩展）

基础插件负责本地编辑、评论和自动保存。本插件通过 Obsidian 桌面版自带的运行时直接调用你已安装并登录的官方 `lark-cli`；无需另开 Node 服务或端口。两个插件分别安装与启用，纯本地用户只需基础插件。

## 安装与设置

需要桌面 Obsidian **1.8.0+**、已启用的本地基础插件 **0.0.1**，以及用户自行安装并配置的 [官方 `lark-cli`](https://github.com/larksuite/cli)。Obsidian 应用提供插件运行时；官方 CLI 若是原生可执行文件，无需另外安装 Node。使用 npm 版 CLI 时，仍需满足 CLI 自身的 Node 安装要求。

从 [v0.0.1 发布页](https://github.com/To-Re/feishu-doc-local/releases/tag/v0.0.1) 下载同步扩展 ZIP，将其中的 `feishu-doc-local-sync/` 目录复制到 **Obsidian 库**的 `.obsidian/plugins/`，再在第三方插件设置中启用。目前尚未上架社区插件目录。

在插件设置填入 CLI **可执行文件绝对路径**；固定参数默认 `[]`，可填写官方身份参数，例如 `["--as", "bot"]`。参数只来自可信设置，不来自文章。插件不会自动搜索 CLI、自动认证或保存令牌；本项目不捆绑官方或自研 CLI。

macOS 从 Dock 启动的 Obsidian 可能没有终端中的 `PATH`。npm 版 CLI 可同时填写「Node 可执行文件（可选）」的绝对路径；此时插件使用该 Node 启动 CLI 的 JavaScript 入口，不依赖 `#!/usr/bin/env node` 查找运行时。CLI 路径应指向 npm 提供的 JavaScript 启动文件或其链接，不要填 shell 脚本。原生 CLI 的 Node 字段留空。在终端分别执行 `command -v lark-cli` 和 `command -v node` 可查看安装路径，填写后保存配置；保存本身不会运行 CLI。

应用配置、权限和登录先在自己的终端完成。使用用户身份时，可运行以下命令，并按官方 CLI 提示选择所需权限及完成浏览器授权：

```sh
lark-cli auth login
lark-cli auth status
```

机器人身份使用应用配置和权限，不通过用户 OAuth 登录。具体身份和授权方式见 [官方认证说明](https://github.com/larksuite/cli/blob/main/README.zh.md#认证)。插件不会在同步窗口发起登录，也不能接收密码或处理交互式授权提示。

项目索引默认使用 `~/.lark-review/projects.json`，可在设置中更改绝对路径并与本地服务版共用。正文、评论与资源仍留在文档旁；项目索引不含正文或凭证。

## 使用

公开预览版同步扩展 **0.0.1** 将常用操作放到编辑器顶部：「从飞书导入」、「拉取」、「推送」、「关联设置」、「预览差异」、「同步评论」和「打开飞书」。未关联的 XML 显示「关联」。打开文章和查看关联只读本地记录，不执行 CLI。

也可对 XML 右键选择「本地飞书文档：关联与同步」，或执行「关联与同步当前 XML 文档」命令；尚未打开 XML 时，可以通过命令“从飞书导入新文档”直接导入。

命令面板中的「管理与切换项目」可查看已登记项目、修改项目名称与默认同步方向、将当前 XML 加入纯本地项目。日常打开和切换文档使用 Obsidian 自带文件列表，顶部不重复放项目管理与文档导航按钮。项目列表可与网页版本共用配置文件；属于其他仓库、已移动、缺失或越界的 XML 会说明原因并禁用打开，插件只打开当前库内重新校验过的文档。通过「CLI 与项目路径设置」可以修改索引路径；CLI 留空时仍可保存本地项目配置。

- 「从飞书导入」：输入已有 Docx/Wiki 链接和库内新 XML 路径，读取预览后点击「确认导入为新文档」。目标父目录须已存在，XML、旁置 JSON 或关联记录已存在时拒绝覆盖。导入保留云端块 ID、正文同步基线及资源映射，并建立关联；不会改动飞书文档，也不会自动发送评论。保存后自动打开；若 Obsidian 尚未索引文件，可点击「打开已导入文档」，不会重复导入。
- 选择纯本地、关联已有飞书文档，或新建飞书文档。关联已有文档只建立映射；新建会在再次确认后发布本地正文。
- 点击「拉取」将飞书正文与资源更新到本地；点击「推送」发布当前正文。操作自动保存并检查两端版本，两端都有修改时显示差异，需核对后确认。也可以先打开「预览差异」；执行按钮固定在弹窗顶部。
- 推送或新建飞书文档成功后，自动将飞书确认的正文、块 ID 与资源更新到本地；旧稿和同步记录保存在相邻 `.review-sync-history/`。若云端结果不确定、资源读取失败或本地出现新修改，则保留原稿并提示核对，不盲目重发。
- 「同步评论、回复与处理状态」会先确认，再读取完整云端评论并发送本地增量。可靠块 ID 对应是发送前提；推送后无法可靠确认的评论位置会标记待核对。白板按整图同步，细粒度本地引用保留在评论文字中。
- 同一稿件的所有打开视图在执行前保存并临时锁定，草稿清理落盘后才开始操作；结束后重新读取。未发送评论、无效源码、未应用图源或未处理的恢复记录都会阻止同步。即使该稿件没有打开视图，也需要先通过基础插件的恢复入口处理遗留草稿。

如果当前项目配置文件没有这篇文章，但旁置 JSON 中已有正文或评论同步记录，窗口会显示「发现已有飞书同步记录」，不会将它当作新文档。可明确选择「恢复已有飞书关联到项目列表」：只补充本地登记，保留正文、评论、云端文档 ID 和待定记录，不执行 CLI。评论记录已保存 URL 时可复用；只有正文 `contentSync.documentId` 时，需补充同一 ID 的 Docx 地址，或在设置中选回网页原来的项目配置文件。新的 Wiki 地址无法离线核对，不能用于此恢复。

已有本地项目的登记 ID 保留；若原项目列表完全缺失，旁置 JSON 没有保存旧项目 UUID，只能生成新的本地登记 ID，云端文档与块 ID 不变。正文与评论记录 ID 冲突，或同一飞书文档已属于其他本地项目时拒绝恢复。

不自动替换关联、不删除云端评论、不在失败后盲目重试。CLI 超时、卸载或回执不确定可能已发生云端写入，此时相邻 JSON 保留待定记录，请先核对再继续。操作记录和下载资源是私人数据，发布源码时不要包含它们。

导入和正文拉取将下载资源放入稿件旁的 `feishu-assets-*` 可见目录，以便 Obsidian 索引；原 `.review-assets-*` 缓存不批量迁移，下次需要下载时使用新目录。导入原文和部分失败记录保留在相邻 `.review-import-*` 中。

CLI 调用使用固定参数数组，不经过 shell，启动后立即关闭标准输入。工作目录使用宿主提供的 vault 根目录，使官方 CLI 能向库内保存资源；文章不能改变执行路径或参数。macOS 上每次调用有独立进程组；取消、超时或卸载会终止该调用及其后代进程。终止进程不能撤回已经提交到飞书的写入。异常回执保留为私有错误信息，界面不直接展示 CLI 原始输出；出现未确认结果时，应核对同步记录后再决定下一步。

## 验证边界

本次首个公开版本统一编号为 **0.0.1**。下方的 0.3.0 为发布前内部迭代号，保留用于追溯。首版是预览版；真实发布、评论云端同步与完整双向往返仍待验收。

自动化测试使用临时文件、模拟宿主和 CLI 回执，不触发登录或云端写入。同步扩展 `0.3.0` 已在真实 Obsidian 1.12.7 窗口中通过官方原生 CLI `1.0.95` 导入授权测试稿：预览时不创建目标文件，确认后生成新 XML、旁置 JSON、项目登记及 18 个可见资源，并自动打开。独立回读确认正文与云端一致、块 ID 和同步基线保留，原测试稿 XML/JSON 哈希不变；图片与附件实际显示。随后通过顶栏直接预览、确认拉取，双方备份及本地更新通过核对。真实发布、评论云端同步和完整双向往返仍待验收。历史网页版本的 CLI 验收不能代替插件结果，见 [2026-09-13 验证记录](../docs/validation-2026-09-13-plugins.md)。

## 构建

在仓库根目录执行：

```sh
npm ci
npm ci --prefix obsidian-sync-plugin
npm run typecheck --prefix obsidian-sync-plugin
npm test --prefix obsidian-sync-plugin
npm run build --prefix obsidian-sync-plugin
```

输出为 `obsidian-sync-plugin/dist/`。保留 `LICENSE`、`THIRD_PARTY_NOTICES.md` 和 `licenses/`；开发构建需要 Node，普通用户无需安装这些开发依赖。
