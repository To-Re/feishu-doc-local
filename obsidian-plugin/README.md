# 本地飞书文档 · Obsidian 基础插件

在 Obsidian 内编辑飞书 DocxXML、写评论，让 AI 直接读取本地文件继续改稿。插件复用网页端的编辑器、解析器、公式和白板渲染，无需安装 Node、启动本地服务或登录飞书。

## 本地能力

- 编辑、只读和源码模式。常见文字、列表、提示块、代码、表格与合并单元格、分栏、图片、公式和部分白板可渲染；支持的内容可直接编辑，未知结构保留原 XML。
- 在编辑或只读模式选中文字评论；图片、公式、附件和白板可整体评论。评论支持回复、解决、重新打开和定位；可靠的本地白板组件引用保留在相邻 JSON 中。
- 正文与已提交评论自动保存到 `article.xml` 和 `article.review.json`。外部 AI 修改时，空闲编辑器回读；存在未保存输入时提示冲突，不能静默覆盖。
- 左侧目录按实际 h1–h9 标题层级跳转并可在固定位置收起；不要求文档从一级标题开始。源码模式点击目录会回到有效正文，无效源码则提示先修正；命令可在库内新建文档或选择已有 XML。
- 公式与支持的白板源码可在侧栏预览并应用。未应用的修改不会冒充已写入 XML。
- 无效源码、未发送评论/回复以及未应用图源草稿写入插件本地恢复记录。重新打开对应文档时显示恢复入口，执行“恢复未保存草稿”后明确选择恢复，磁盘文件变化则提示冲突。不同视图使用独立恢复记录。

恢复记录位于本插件的本地 `data.json`，可能含完整私人草稿，**不要公开这个文件或整个 `.obsidian` 目录**。AI 平常应读取正式 XML 与旁置 JSON；恢复草稿与已保存文件是两份不同状态。

## 手动安装与体验

1. 从 [v0.0.1 发布页](https://github.com/To-Re/feishu-doc-local/releases/tag/v0.0.1) 下载基础插件 ZIP，将其中的 `feishu-doc-local/` 目录复制到 Obsidian 库的 `.obsidian/plugins/`。保留随包许可证目录。
2. 重新加载 Obsidian，在第三方插件设置中手工启用“本地飞书文档”。目前尚未上架社区插件目录。
3. 将 XML、相邻 `.review.json` 和资源目录一起放入库中，保持相对路径。
4. 点击 XML，或执行“本地飞书文档：打开 XML 文档”；也可右键 XML 选择“用本地飞书文档打开”。
5. 编辑正文，选文添加评论，等待“已保存到本地”。告知 AI 读取这两个文件即可继续修改。

命令还包括“新建本地文档”和“恢复未保存草稿”。如果文件树不显示 XML，可在 Obsidian 文件与链接设置中开启“检测所有文件扩展名”。其他插件接管 XML 时，用本插件命令显式打开。

恢复窗口可以回到原文，也可以“恢复为新文档”；后者要求一个不存在的新文件名，保留原恢复记录并移除新文件继承的云同步状态。原 XML 被移动或删除后，仍可通过这个窗口取回最后有效正文和草稿。只有明确确认丢弃才删除对应恢复记录，不删除正文或评论文件。

重命名单篇 XML 时，插件会为新名称复制评论旁置文件并保留旧旁置文件；同名目标已存在则停止迁移并提示，不能覆盖另一篇稿件的评论。整目录移动会沿用一同移动的旁置文件。跨目录移动单篇 XML 不会自动移动或覆盖素材，需要把相对引用的资源一起迁移。

## 可选飞书同步扩展

文档切换使用 Obsidian 自带的文件列表；新建 XML 可用命令面板中的“新建本地文档”。顶部不重复放文档导航或项目管理按钮。基础插件不调用 CLI、不访问飞书。需要导入、发布或持续同步时，安装并启用独立的 [本地飞书文档 · 飞书同步](../obsidian-sync-plugin/README.md)，配置你自己已登录的官方 CLI。

公开预览版基础插件 **0.0.1** 配合同步扩展 **0.0.1**，会在当前文档顶部显示「从飞书导入」、「拉取」、「推送」、「关联设置」、「预览差异」、评论同步与飞书链接；尚未关联的文档显示「关联」。开启或关闭扩展时，工具栏随之更新。

扩展先通过基础插件保存并锁定当前文档，再执行点击的拉取或推送；未完成草稿会阻止同步，两端都有修改时需要核对差异后确认。差异预览是可选入口。推送及新建飞书文档成功后，自动采用飞书确认的正文与资源，旧稿存档；结果不确定、资源读取失败或本地出现新修改时保留原稿，提示核对。评论同步另有确认入口。「从飞书导入」保存为库内新的 XML、旁置 JSON 和资源，先预览再确认，已有文件不会被覆盖。两种插件都不需要另开 Node 服务。

## 范围与限制

本次首个公开版本统一编号为 **0.0.1**。下方验收中的 0.2.0–0.4.0 为发布前内部迭代号，保留用于追溯；它们不是公开版本要求。插件内真实发布及评论云端同步仍待验收。

目前要求 Obsidian 桌面版 **1.8.0+**；独立弹出窗口和移动端不在本次交付范围。不提供原生白板拖拽编辑、电子表格内部编辑器或未下载云端资源的自动加载。PlantUML 和仅有飞书 token 的白板需要已有本地预览缓存；本地渲染不等于飞书视觉完全一致。

文档与资源限制沿用浏览器文件协议：XML 小于 5 MB、额外文本/SVG 预览不超过 2 MB，评论 JSON 还需为恢复日志预留空间。资源路径限定在稿件目录内，不执行 HTML、SVG 脚本或外部链接。XML 与 JSON 使用版本校验及恢复日志；这不等于能锁住任意外部进程。

测试使用公开样例、模拟 vault 和临时文件，覆盖保存、草稿、切文件、关闭、重命名与同步锁；通过官方 Obsidian API 类型检查与构建。Obsidian 1.12.7 中已用基础插件 `0.2.0` 验证正文编辑、自动保存与无效源码保护；`0.3.0` 已验证升级后重开与评论生命周期，尚未重跑完整正文编辑 GUI。草稿恢复和全部资源交互仍需实际窗口验收，见 [2026-09-13 验证记录](../docs/validation-2026-09-13-plugins.md)。自动保存与退出回调也不能保证突然断电或宿主强制终止前的每个按键均已持久化。

## 构建

基础插件 `0.4.0` 已在实际 Obsidian 1.12.7 中验证：仅本地模式的简化工具栏、文档打开后启用同步扩展时动态出现按钮、真实导入新稿后自动打开、目录跳转，以及下载图片与附件的渲染。完整正文编辑与恢复场景的新版 GUI 覆盖仍以后续记录为准。

开发者在仓库根目录执行：

```sh
npm ci
npm ci --prefix obsidian-plugin
npm run typecheck --prefix obsidian-plugin
npm test --prefix obsidian-plugin
npm run build --prefix obsidian-plugin
```

输出为 `obsidian-plugin/dist/`。构建需要 Node；安装已构建插件的普通用户不需要安装这些开发依赖。主代码、字体与许可证都随包提供，不依赖相邻仓库或网页服务。

## 开源与依据

插件代码随主项目使用 MIT。分发保留 `LICENSE`、`THIRD_PARTY_NOTICES.md` 和 `licenses/`；第三方代码与字体沿用各自许可证。Obsidian 应用由用户自行安装，不随本插件打包。

使用官方 [Obsidian API](https://github.com/obsidianmd/obsidian-api) 的文件视图、命令、事件和 vault API；构建采用官方 [示例插件](https://github.com/obsidianmd/obsidian-sample-plugin) 的 CommonJS 与外部 `obsidian` 模块方式。
