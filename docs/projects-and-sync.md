# 项目、配置路径与飞书同步

一个项目管理一份本地 DocxXML，可选关联一份飞书文档。浏览器编辑保存到原 XML，评论、回复、处理记录和同步基线保存到相邻 `.review.json`。项目列表只负责找到这些文件并记住关联；它不收纳正文，也不代替旁置反馈。

## 打开和创建项目

按 [README](../README.md#本地启动) 构建并启动。`--file` 指定初始文章，省略时使用欢迎稿；启动文件会登记到项目列表。顶部下拉框切换已登记项目，一级按钮“新建项目”可以选择已有 XML 或在已有目录中创建新的 XML。页面支持绝对路径和 `~/` 主目录简写；新建时填以 `/` 结尾的目录，会按项目名生成 XML 文件名并显示完整目标。未填位置时使用当前文章目录；不支持 `~其他用户` 或环境变量展开。父目录需已存在，可先建立目录，例如 `mkdir -p ~/articles`。

创建时按本地文件与飞书来源组合处理：

| 本地来源 | 飞书来源 | 明确提交后的行为 |
| --- | --- | --- |
| 已有 XML | 仅本地 | 登记项目，保留正文和反馈 |
| 新 XML | 仅本地 | 创建含标题和空段落的文件，再登记项目 |
| 已有 XML | 已有飞书文档 | 回读并验证飞书身份，只建立关联，不覆盖已有本地稿，也不发布到云端 |
| 新 XML | 已有飞书文档 | 首次拉取飞书正文到新文件，缓存可支持的资源，建立同步基线 |
| 已有或新 XML | 新建飞书文档 | 点击“创建项目并新建飞书文档”后，将本地稿作为初始正文创建云文档并回读 |

新文件的正文或相邻反馈只要已存在，创建就会拒绝，不通过覆盖文件完成“新建”。同一索引中，一份本地文件只能登记一次，一份实际飞书 Docx 文档也只能绑定一个项目。输入已有 Wiki 链接时，服务先解析实际 Docx 身份；不把 Wiki token 当成文档 ID。

“切换文档”选择另一份本地 XML，已登记项目会恢复关联；这不会向当前项目增加另一篇正文。未登记文件不会沿用上一个项目的云端目标；要为它建立项目，应使用新建项目中的“选择已有 XML”。新建弹窗的“浏览”只帮助填写路径，选完会恢复原项目，确认创建之前不会切换当前稿件。

切换、创建或同步前会先保存当前稿件。未发送评论、回复和未应用的公式或白板草稿，需要先完成或取消；操作期间编辑与表单输入暂时禁用。失败保留输入，迟到响应不会覆盖期间出现的新修改。创建若已登记但后续步骤失败，可能返回带警告的项目；看到项目并不等于所有云端步骤成功。

## 配置本机 CLI

仅本地项目不需要 CLI。飞书项目通过官方命令协议调用已有 CLI，不内置登录或凭证管理。在本机创建 `~/articles/cli.json`：

```json
{
  "command": "lark-cli",
  "args": ["--as", "bot"]
}
```

启动示例：

```sh
npm start -- --file ~/articles/article.xml --cli-config ~/articles/cli.json --projects-file ~/articles/review-state/projects.json
```

`command` 也可用可执行文件完整路径。其他 CLI 实现需提供相同的官方命令、DocxXML 与 JSON 回执约定；项目不绑定特定替代实现。

示例配置路径需替换为实际值；JSON 内的 `~` 不由阅稿器展开。CLI 配置只从启动参数指定的本机文件读取，不从文章、项目索引或 HTTP 请求中执行命令。

| 参数 | 作用 |
| --- | --- |
| `--file` | 初始本地 XML；省略时使用欢迎稿 |
| `--port` | 本机 loopback 端口，默认 `4318` |
| `--cli-config` | 多项目共用的可信本机 CLI `command,args`；各项目分别保存云目标 |
| `--projects-file` | 显式使用指定实例索引；省略时全新安装使用 `~/.lark-review/projects.json`，旧实例保留原索引 |
| `--cloud-config` | 兼容原固定文件配置，含 `command,args,documentId,url`，要求同时指定 `--file`；不能与 `--cli-config` 同用 |

关联已有文档需要 CLI 能完整读取它；发布、评论、附件与白板操作还需要各自权限。文档可编辑与应用 API scope 是不同条件。阅稿器不猜测当前浏览器用户身份；使用支持管理员授权的 CLI 时，由该 CLI 的明确本机配置指定账号，创建后授予 `full_access` 并回读确认。具体配置字段与支持的身份类型由 CLI 实现决定，不能假定官方 CLI 内置相同配置。身份配置留在本机，不写进共享项目索引；管理员授权与转移所有者、发送通知是不同操作。

授权响应可能回显邮箱，而列表使用 Open ID。缺少准确映射时，CLI 会分别记录已确认的写入和未完成的身份核验（`identity_unresolved`），不自动重复授权。页面在当前会话中保留“创建时提示”，可以主动关闭；它是历史结果，不代表云端权限的实时状态。

没有配置管理员时，可选择已授权的已有文档，或在新建时填写已给相关身份授权的飞书文件夹 Token。若 CLI 回执提示权限未授予，先处理同一文档的权限，不重复创建。正文创建成功与权限确认分别记录；权限失败提示会显示在页面，完整回执仅保存在本机同步历史。

## 文件保存在哪里

| 内容 | 位置 |
| --- | --- |
| 当前正文 | 选中的 `article.xml`，例如 `~/articles/article.xml` |
| 评论、操作、资源映射、同步基线 | 同目录 `article.review.json` |
| 显式拉取的资源 | 文章目录内新建的 `.review-assets-…` 文件夹；实际路径写入反馈的 `resources` |
| 项目索引 | 当前配置目录的 `projects.json`；全新安装默认 `~/.lark-review/projects.json` |
| 本实例选择的配置位置 | 启动实例目录中的 `project-settings.json`，兼容旧配置格式 |
| 正文同步前快照及回读记录 | 实例索引同目录的 `sync-history/<操作目录>/` |

顶部第一层集中显示当前项目、本地正文路径、飞书目标以及“拉取”“推送”“关联设置”和可选差异预览；第二层是编辑模式、文字格式与评论。目标链接在评论区关闭时仍可直接打开。

顶部路径栏显示当前选中资源的完整路径，并可复制；预览资源时另提示正文同步仍针对 XML。文件栏列出 XML 和反馈 JSON，点击文件可查看其完整路径。文件栏使用顶栏左上角固定的同一个按钮展开或收起，位置、大小和焦点不变；重新展开保留当前资源、目录状态和滚动位置。项目选择列表固定向下展开，展示名称、路径和当前项目标记；方向键浏览，Enter 或空格确认，Escape 或 Tab 关闭。“项目管理”显示实际生效的“项目配置路径”；点击“修改”进入编辑，保存成功才更新显示。

文章是 UTF-8 DocxXML，不是 Word 的 `.docx`。资源树只列当前文章、反馈与明确引用的文件，不扫描索引所在目录。共享索引和同步历史也不会混入正文。私有文档 ID、链接、完整云回读及截图留在本机受控目录；默认 `.local` 已忽略 Git，自定义目录也应排除这些材料，不能把运行数据作为公开样例提交。

## 显式同步正文

点击“拉取”将飞书正文与资源更新到本地，点击“推送”发布本地正文。页面先保存当前编辑，并在内部校验本地文件、云版本和素材；两端都有修改时显示差异，需要核对后再确认。执行中输入暂时禁用，刷新或关页会提醒正在进行的操作。

“预览差异”是可选的只读入口，可左右对照或合并显示，红色删除、绿色新增并标出行内改动，连续相同内容可展开。执行按钮放在弹窗顶部；关闭预览不会执行同步。新建项目时保存的 `defaultDirection` 只决定默认展示哪个方向的差异，点击“拉取”或“推送”直接选择本次操作。

准备后出现本地修改、云版本变化、素材变化或超过五分钟有效期，都需要重新准备；服务重启也会丢弃内存中的预览 ID。首次没有共同基线时，建议先查看差异，核对将被覆盖的一端。

拉取会采用云正文并缓存支持的图片、附件与白板预览，保留本地评论。白板内部可在 token 不变时修改，因此拉取会刷新其缓存，组件评论位置需要重新确认。它不等于本地已经具备电子表格或原生白板的完整内部编辑器。

推送优先按真实块 ID 替换改动块或追加内容，结构无法可靠对应、或者需要重新上传已变素材时可能替换整篇正文。预览会提示块 ID 和评论引用可能变化。每步发布后完整回读，未知结构和复杂媒体仍受 [格式范围](../README.md#当前格式范围) 限制。

飞书可能调整颜色、间距、空段落、分栏或其他格式，也可能丢失某些内容。推送成功后，完整读取并核对云端正文与资源，自动更新本地工作稿，使真实块 ID 和同步基线一致。同步目录分别保存更新前的 `local.xml`、`local.review.json`、云端 `cloud.xml` 和完整回执；反馈中的操作记录写明存档位置，人或 AI 可随时读取旧稿核对。

结果不确定、资源读取失败、云版本再次变化或期间出现本地修改时，停止覆盖并保留旧稿与恢复记录，不盲目重发。对于旧版本已经发布、但尚未更新本地的记录，再次推送会只完成本地更新，不重复发布。

正文同步不会把评论一并发布。评论区“同步飞书评论”独立交换意见、回复和解决状态；白板组件意见在云端按整图处理，本地组件引用继续保存。完整规则见 [评论协议](protocol.md#显式飞书评论同步)。

## 先本地写作，再关联飞书

纯本地项目不需要 CLI，也不需要云文档 ID。准备发布时，点击工作区右上角的关联入口。此操作更新当前项目，不重新登记同一文件、不复制文章。未配置 CLI 时表单会说明连接要求，不发起登录。

- **关联已有文档**：只完整回读并验证目标身份，然后更新项目索引；不改两端正文和旁置评论，也不直接建立“已同步”基线。之后直接选择拉取或推送，也可先查看差异。
- **新建并发布当前文章**：提交明确创建一篇云文档，发布当前已保存的稿件，成功后自动更新本地正文与资源并建立同步基线，旧稿存档；项目 ID、本地路径及评论 ID、回复保留。创建超时或回读身份错误时保存 pending 和回执，不自动重新创建。

首次发出时去除文档块 `id` 和 `comment-refs`，飞书分配真实块 ID；白板内部图形 ID 不作为 Docx 块 ID。成功创建或发布后，旧 XML 存档，飞书确认的真实块 ID 写入本地工作稿与 `contentSync` 基线；`contentSync.documentId` 与双方基线限制后续同步所属文档，不额外维护可能漂移的第二张位置映射表。

推送更新本地后，只有真实块 ID 与内容可可靠对应的引用继续定位；没有云 ID 的本地选区、已重建的块和白板组件身份变化均保守标为待确认，评论文本与回复保留。不按重复文字搜索猜位置，也不自动升级已删除或待确认引用。

同一项目已有飞书关联、索引中云文档重复、旁置记录指向别的文档或有未确认操作，均拒绝重新绑定。当前不提供解除或更换飞书绑定。

## 项目配置路径与浏览器缓存

“项目管理”只显示当前实际生效的“项目配置路径”和“修改”按钮。点击后编辑目录，再点“保存”；取消、未改目录或失败都不会切换。默认目录为 `~/.lark-review/`，目录中保存 `projects.json`。全新安装使用默认目录；已有旧设置或旧实例索引保留原位置，`--projects-file` 显式指定的位置也会保留。

保存新目录时，服务合并当前和目标的项目登记，成功后切换索引；保留源索引，不搬移正文。目标目录不必预先存在，服务在明确保存时创建它。相同文档的绑定冲突、同一 ID 指向不同文件等情况会拒绝切换，页面保留输入，原配置继续生效。

同一台机器上能访问同一目录的程序可复用登记文件；这不会自动同步不同电脑上的文章、文件路径或飞书内容。Obsidian 同步扩展默认复用 `~/.lark-review/projects.json`，可与本地服务版共用项目列表。静态浏览器版和 Obsidian 基础插件使用各自的目录或库内文件导航，不管理此索引。

浏览器仅以 `lark-review.last-project` 缓存最近项目；配置路径以服务端保存值为准，不采用旧的未提交目录缓存。清空浏览器缓存不会删除索引、正文或评论。

刷新页面后，仅当完整服务端列表中仍有最近项目、且没有待保存内容或草稿时，才通过打开项目接口恢复它；失效 ID 不用于猜测路径。窗口重新获得焦点时只刷新列表，其他客户端登记的新项目可出现在下拉框中，不替换当前正文、不触发飞书同步。

## 供后续客户端复用的索引格式

项目索引是 UTF-8 JSON，顶层只含 `version` 和 `projects`。以下为脱敏示例；实际 `localPath` 必须是规范化绝对路径，不能写 `~`，占位云 ID 应替换为完整回读确认的实际 ID：

```json
{
  "version": 1,
  "projects": [
    {
      "id": "review-example",
      "name": "示例文章",
      "localPath": "/articles/article.xml",
      "defaultDirection": "pull",
      "cloud": {
        "documentId": "DOC_ID",
        "url": "https://example.feishu.cn/docx/DOC_ID"
      },
      "createdAt": "2026-09-12T00:00:00.000Z"
    }
  ]
}
```

纯本地项目省略 `cloud`，不要写成 `null`。`id`、名称、本地路径、默认方向、创建时间为必填；`defaultDirection` 仅支持 `pull/push`。同一列表的 `id`、`localPath` 与已绑定的 `cloud.documentId` 分别唯一。当前选中项目不写入共享索引。未知字段、错误版本和重复绑定会报错，不能随意把客户端私有设置塞进记录。

`project-settings.json` 是本实例设置，不是项目索引。它含 `version:1`、`shared`、可选 `sharedPath` 和服务管理的 `localBaseline`。这些字段继续兼容旧客户端，界面不再提供共享开关。HTTP 设置回读提供实际 `path`、`defaultSharedPath` 和 `hasSharedPath`；界面从 `path` 取得当前目录，保存新位置沿用 `{shared:true,path:"/目录/projects.json"}`。

未来客户端优先通过本地 [HTTP 接口](protocol.md#本地-http) 访问，沿用同源与 CSRF 校验、文件版本及同步保护。若直接写索引，需要遵守同版本字段校验、规范路径与唯一绑定约束，以及 `.lock`、写前重读和原子文件替换约定；单纯读取同一 JSON 不等于已支持多端安全写入。CLI 身份配置由各实例启动时提供，共享索引不携带登录态或执行命令。

## 未完成同步如何处理

本地双文件版本比较可发现正文或反馈冲突；云端写前回读和 CLI `--revision-id` 可减少误覆盖。但本地文件、CLI 与飞书之间没有原子的比较更新事务，无法锁住所有外部编辑，分步云写也可能只完成一部分。

云创建或发布前先在 `contentSync.pending` 写入意图，评论发送前写 `cloudSync.pending`；拿到并保存完整确认结果才清除。同步前后的快照在实例的 `sync-history`，评论映射和发送意图仍在相邻反馈。超时、响应丢失或资源下载失败不代表云端未执行。

出现待定提示时先保留 XML、反馈和快照，确认是否仍有同步进程，再完整回读目标飞书文档或评论，核对已有回执及真实 ID。已成功部分应恢复对应映射或基线；明确确认未执行后才能考虑重试。不要删除 pending、换一个文件名或重新创建项目来绕过暂停，否则可能重复创建云文档或评论。`.review.json.sync.lock` 是同稿同步锁，异常退出后需在确认没有活跃进程且处理完待定结果后才能清理。

当前没有自动恢复按钮，也没有跨云服务的幂等保证。新本地文件的首次拉取若资源或基线写入失败，会保留文件和已登记项目并显示警告，先检查已保存内容，再重新预览拉取。同步时产生的新本地输入保留在页面，遇到冲突需人工核对，不能用旧响应覆盖它。
