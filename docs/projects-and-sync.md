# 项目与飞书同步

一个项目对应一份本地 DocxXML，可选关联一份飞书文档。正文保存在 XML，评论和同步记录保存在相邻 `.review.json`；项目列表只记录文件位置和飞书关联。

## 创建与切换

本地服务按[首页步骤](../README.md#本地网页版)启动。在“新建项目”中可以选择已有 XML，也可以创建新文件；先选“仅保存在本地”，成熟后再关联飞书。

| 操作 | 结果 |
| --- | --- |
| 新建本地项目 | 创建新 XML，或登记已有文件；已有正文和评论不会被覆盖。 |
| 切换文档 | 打开另一份本地 XML；已有项目会恢复自己的关联，不会加入当前项目或沿用上一份的飞书目标。 |
| 关联已有飞书文档 | 读取并验证目标身份，建立关联；已有本地稿不被覆盖。随后预览差异并确认同步。 |
| 从飞书导入 | 保存为新的本地 XML，下载支持的资源；目标文件已存在时拒绝覆盖。 |
| 新建飞书文档 | 明确确认后，以当前稿件创建云文档；成功后回读更新本地，原稿存档。 |

本地文件位置支持绝对路径和 `~/`；新建时也可填写以 `/` 结尾的目录，按项目名生成 XML 文件名。父目录需已存在。同一项目索引内，本地文件与实际飞书文档的绑定分别唯一；Wiki 链接会解析为实际 Docx 文档。

Obsidian 使用库内文件列表或命令面板切换、新建 XML。[同步扩展](../obsidian-sync-plugin/README.md)提供关联和导入入口。当前不支持更换已有项目的飞书绑定。

## 连接官方 CLI

仅本地写作不需要 CLI。需要同步时，先按[官方 lark CLI 说明](https://github.com/larksuite/cli)安装、配置身份和权限。编辑器不负责登录，不保存访问令牌，也不会在启动或自动保存时调用 CLI。

本地服务使用一个可信配置文件，例如 `~/articles/cli.json`：

```json
{"command":"lark-cli","args":["--as","bot"]}
```

```sh
npm start -- --file ~/articles/article.xml --cli-config ~/articles/cli.json
```

`command` 可填写可执行文件绝对路径；JSON 中的 `~` 不会展开。发布时 CLI 在文章目录执行，固定参数中的脚本或配置文件也应使用绝对路径。`--as bot` 使用机器人身份，账号身份和可用权限以 CLI 的实际配置为准。文档访问权与 API 权限都需要满足；新建成功不代表个人账号自动获得管理权，权限提示应在同一文档上处理，不要重复创建。

| 启动参数 | 用途 |
| --- | --- |
| `--file` | 初始 XML；省略时使用欢迎样稿。 |
| `--port` | 本机端口，默认 `4318`。 |
| `--cli-config` | 本机 CLI 程序和固定参数。 |
| `--projects-file` | 指定项目索引；省略时新安装默认使用 `~/.lark-review/projects.json`，已有实例保留原位置。 |
| `--cloud-config` | 兼容旧版固定目标配置，必须配合 `--file`，不能与 `--cli-config` 同用。 |

Obsidian 在同步扩展设置中填写官方 CLI 独立可执行文件的绝对路径，Node 字段留空，无需额外安装 Node。若使用 npm 的 JavaScript 启动入口，可同时指定系统 Node 路径，详见[扩展设置](../obsidian-sync-plugin/README.md#安装与设置)。文档内容和项目索引不能指定要执行的程序。

## 拉取、推送和评论

1. 点击“预览同步”，先保存当前修改，再读取云端正文。
2. 选择方向：“飞书 → 本地”是拉取，“本地 → 飞书”是推送。
3. 核对差异，在预览顶部确认执行。关闭窗口不会同步。

差异支持左右对照与合并视图，红色表示删除、绿色表示新增。切换方向会重新预览；本地内容、素材、云版本改变或预览超过五分钟，需要重新读取。未发送的评论、无效源码和未应用的图源草稿应先处理。

**拉取**会先备份本地正文和评论，再更新正文及支持的资源缓存，保留评论。**推送**优先更新对应块；结构无法可靠匹配时可能替换整篇，预览会提示块 ID 和评论引用的变化。成功后完整回读飞书正文与资源，更新本地工作稿，旧稿和回执仍保留在快照中。

飞书可能规范化格式，甚至存在特定 CLI 版本的内容丢失问题；先用副本核对[格式差异](style-coverage.md#飞书往返的已知差异)。只保留原 XML 不等于所有云端结构都能无损发布。

“同步评论”是独立操作，交换新增意见、回复及解决状态，不发布正文。白板组件评论在飞书按整张白板定位；已发送评论的正文改写不会自动覆盖云线程。全文评论或仍为已解决状态的云评论可能不接受回复，界面会保留未发送内容并说明原因。

## 文件与项目配置

| 内容 | 保存位置 |
| --- | --- |
| 正文与评论 | `article.xml` 与相邻 `article.review.json` |
| 下载资源 | 稿件目录内的新资源目录，实际引用写入 JSON |
| 项目索引 | 当前配置目录的 `projects.json`，新安装默认 `~/.lark-review/projects.json` |
| 网页同步快照 | 当前项目配置目录的 `sync-history/` |
| Obsidian 同步快照 | 稿件旁的 `.review-sync-history/` |

网页的“项目管理”显示当前项目配置路径，可修改并保存。切换配置目录会合并项目登记，保留源索引，不搬移文章；重复或冲突绑定会阻止切换。Obsidian 同步扩展选择同一 `projects.json` 后可共用项目列表；它不会自动把文件同步到另一台电脑。

静态浏览器版和 Obsidian 基础插件使用各自的目录或库内文件导航，不管理共享索引。文件格式和接口细节见[本地协议](protocol.md)。

## 恢复上一快照

网页进入“项目管理”，Obsidian 进入“关联设置”，选择“恢复上一快照”。先看差异，确认后恢复本地正文和评论；飞书不改变。恢复前另存当前版本，因此可以再次预览并恢复回来。

恢复保留当前已确认的云端身份与发送记录，避免旧评论重复发送；引用位置可能需要重新确认。较新的本地评论保存在恢复前快照中。

快照包含 XML、评论 JSON 和资源校验信息，**不会复制所有图片附件**。资源必须仍在原位置且未改变；缺失、变化、快照损坏或预览后出现新修改时会阻止恢复。早期快照没有资源历史校验值，会提示人工核对。

网页可识别当前配置目录、原实例目录及稿件旁的历史；Obsidian 可识别稿件旁和当前配置目录的历史。找不到旧快照时，先切回原配置或原网页实例，不要移动别的文章快照来替代。

## 同步未完成时

超时或下载失败不代表飞书没有执行。看到“结果未确认”时，保留 XML、JSON 和快照，核对飞书当前内容及回执；不要删 `pending`、重建项目或盲目重发。恢复快照也不能绕过待确认的云操作。

本地文件与飞书之间没有跨端原子事务，多个外部编辑器也无法被同时锁住。发生冲突时先保留并核对两份内容；[安全说明](../SECURITY.md)和[协议](protocol.md)列出详细边界。
