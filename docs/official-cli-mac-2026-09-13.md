# 官方 CLI 的 Mac 实测

2026-09-12 至 13 日，在 macOS 26.4.1 / Apple Silicon 上，使用 GitHub 发布的 [lark-cli v1.0.95](https://github.com/larksuite/cli/releases/tag/v1.0.95) `darwin-arm64` 二进制完成真实云端验收。本次直接使用该官方发行版，修复候选的结果单独记录。

结论：阅稿器可以直接使用官方 CLI 完成下列已验收流程。替代实现需适配相同命令、DocxXML 和 JSON 回执边界；命令兼容不意味着不同实现、不同发行版本的全部能力和缺陷相同。旁置 `*.review.json` 仍是阅稿器自己的本地协议。

## 已验证的流程

| 流程 | 真实结果 |
| --- | --- |
| 页面新建项目和飞书文档 | 以已有本地 XML 创建独立测试文档，包含标题、段落、粗体、斜体、行内代码、表格、图片、Card 附件和 Mermaid 白板。随后用官方权限接口授予配置的文档管理员 `full_access`。 |
| 飞书正文与资源拉回 | 采用完整 XML 回读；PNG 和 52 字节 TXT 下载后与原文件 SHA-256 相同，白板 JPEG 预览非空。 |
| 浏览器编辑 → 本地文件 → 飞书 | 实际编辑第一段，自动落盘，预览并确认推送。revision 4 → 5，仅目标段落换了块 ID；独立官方 CLI 回读与本地 XML、旁置同步基线逐字一致。 |
| 飞书修改 → 本地文件 → 浏览器 | 独立官方 CLI 修改第二段，并追加附件边界样例；页面确认拉取到 revision 8，正文与独立完整回读逐字一致，第一段编辑和本地评论保留。 |
| 白板评论与回复 | 在本地选中一个白板组件并评论；云端产生一个白板块评论，文字包含组件名称。本地回复获得真实云端回复 ID。 |
| 评论状态与反向回复 | 页面解决并同步，独立 CLI 回读 `is_solved=true`；页面重新打开并同步。独立 CLI 新增另一条回复，随后在本地显示。 |
| 重复同步 | 最终保持 1 条评论、2 条回复，状态为打开，无待确认写入；再次同步新增、回复、状态更新均为 0。 |
| 三方检查 | 本地浏览器、XML/JSON 文件、Chrome 飞书页面均核对。飞书页面可见三节点白板、卡片附件和评论回复；本地图形布局有差异，不声明像素一致或原生节点编辑往返。 |

## 已确认的边界

- **官方 v1.0.95 仍丢失行内附件后的文字。** 向独立测试文档追加 `<p>OFFICIAL_INLINE_BEFORE <source token="…" name="note.txt"/> OFFICIAL_INLINE_AFTER</p>`，命令成功，但完整回读和 Chrome 页面均没有 `OFFICIAL_INLINE_AFTER`。Card 附件正常。此处保存发行版的失败证据，没有用候选补丁掩盖结果。
- 云端会规范化标题、表格结构和图片属性。创建后的差异需要预览采用；不能要求输入 XML 与首次回读字节完全相同。
- 白板评论在云端定位到整张白板；本地组件引用保存在旁置 JSON。正文拉取会保守地把已有组件位置标为待确认，评论和回复本身保留。
- 创建时使用纯应用身份、没有当前用户标识，官方 CLI 跳过自动授予当前用户访问权。本次另行通过官方权限接口给已配置管理员授权；不代表任意用户安装后都会自动获得访问权。
- 本次未验证 Intel Mac、Windows、Linux、所有样式、电子表格内部编辑或跨文档复制白板。没有把空附件的离线适配测试写成云端上传成功。

## 修复与复核

下载适配层原来拒绝 `size_bytes=0`，会误报合法空附件。现允许非负整数，继续核对实际文件大小、路径、普通文件类型和私有权限；负数、非整数、缺失大小及回执与文件不一致仍拒绝。图片和白板仍经过图像内容校验。

- 定向测试：`npm test -- tests/content-cli.test.ts`，41 项通过。
- 全量测试：`npm test`，41 个文件、475 项通过；需要允许测试监听本机回环地址。
- `npm run typecheck`、`npm run build` 通过。
- 独立复核重新计算发行包、实际二进制、资源缓存和受保护原文件哈希，并复核推送阶段证据。4 个既有正文/评论文件未修改。
