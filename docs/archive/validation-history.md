# 阅稿 · 飞书格式

打开本地 DocxXML，在浏览器直接修改、选文评论。正文写回原文件，反馈自动保存到相邻 JSON；外部 AI 读取这两个文件即可继续改稿。

这是独立本地应用，没有内置模型或飞书登录流程。

交互参考 [Human Review](https://github.com/petergyang/human-review)：让人直接在文章上表达意见，由现有 AI 工具接着处理。本项目增加专门的 DocxXML 保留与转换层，正文和反馈分别自动落盘；没有复制 Human Review 的代码或运行时依赖。

## 本地启动

需要 Node.js 22.13 或更新版本。

```sh
npm ci
npm run build
npm start
```

打开 `http://127.0.0.1:4318/`。初次启动将格式样稿复制到 `.local/welcome.xml`，以后继续使用这份文件，不覆盖你的修改。评论位于 `.local/welcome.review.json`。这个文件在第一条评论或第一次正文编辑保存时建立。

顶部提供 **编辑 / 只读 / 源码** 三种模式。源码显示当前 DocxXML，合法修改自动保存到原文件，不自动排版；保留未知 XML、注释及原文件统一使用的 CRLF 换行。未闭合标签等输入会保留在页面中并显示错误，不写入文件；可切只读预览最近有效内容，修正或“还原源码”后继续编辑。未完成的源码会阻止切文件、切项目及飞书同步，关闭页面会提示尚未保存。整篇源码改动保留评论、回复和同步记录，原评论引用位置标为待确认；选择正文评论仍在编辑或只读模式进行。只切模式不会触发保存。

打开自己的文章：

```sh
npm start -- --file /absolute/path/article.xml --port 4318
```

启动文件会登记为本地项目。顶部“新建项目”和“切换文档”是一级按钮，悬停或键盘聚焦可查看用途。新建可选择已有 XML 或在已有目录中创建新文件，不覆盖已有正文或旁置评论。一个项目对应一份本地 XML，可选关联一份飞书文档。“切换文档”选择另一份本地 XML；macOS 弹出系统文件选择窗口，其它系统填写完整路径。已有项目会恢复关联，未登记文件不会沿用上一项目的飞书目标，也不会添加到当前项目。

先写本地稿即可：新建时选“仅保存在本地”。新建文件支持 `~/`，目录以 `/` 结尾时按项目名生成 `.xml` 文件名，页面显示完整保存位置；父目录需已存在。文章成熟后，点工作区右上方“关联飞书”，可关联已有文档或新建并发布当前文章，原项目 ID、本地路径和评论保留。已有文档只建立关联，后续仍先预览差异再确认同步。

文章保存的是官方 CLI 的 **DocxXML 文本**，不是 Word 的 `.docx` 压缩文件，也不把普通 HTML 直接当作官方格式。

## 多项目与飞书正文同步

“预览同步差异”提供类似 Git diff 的左右对照和合并视图：按 XML 块分行，红色标删除、绿色标新增，行内强调具体修改；连续相同内容默认折叠。左侧是将被覆盖的“同步前”，右侧是所选来源的“同步后”，随同步方向变化。这里的展示行号不是原文件物理行号；单行 XML 也能逐块比较。完整原文仍可展开查看，预览不会改写或格式化源文件，确认后才执行同步。

差异展示保留空白、属性顺序和块 ID 的变化。大文档按需分段显示；超过结构比较预算会明确提示并保留完整原文入口，长行可能只标记整行增删。正文 XML 相同不代表白板或其他资源相同，是否需要同步仍以同步预览的状态与提示为准。

纯本地使用不需要配置 CLI。需要从页面关联或新建飞书文档时，在本机准备 CLI 配置，例如 `~/articles/cli.json`：

```json
{"command":"lark-cli","args":["--as","bot"]}
```

```sh
npm start -- --file ~/articles/article.xml --cli-config ~/articles/cli.json --projects-file ~/articles/review-state/projects.json
```

`--cli-config` 只指定可信本机可执行程序和参数，不绑定文档；飞书目标由项目保存。CLI 身份与权限需事先配置，阅稿器不发起登录。全新安装的项目索引默认使用 `~/.lark-review/projects.json`；已有实例保留原配置和项目列表，`--projects-file` 仍可显式指定实例索引。它不搬移文章，也不把评论集中到索引里。原来的 `--cloud-config` 仍可用，与 `--cli-config` 二选一，见下方评论指南。

在“新建项目”中选择本地文件及飞书来源。已有本地文件关联已有飞书文档时只建立关联；新本地文件关联已有飞书文档会首次拉取；明确选择“新建飞书文档”并提交才创建云文档。bot 新建成功不代表当前浏览器用户自动获得权限，适合填写双方已获授权的飞书文件夹 Token，或直接使用已授权的已有文档。

顶部集中显示当前项目、本地文件路径和可直接打开的飞书目标；编辑和评论工具位于下一层。选择同步方向后点击“预览同步差异”，先保存本地并显示两端正文预览，核对覆盖方向与警告后，再点明确的确认按钮才执行。正文同步与“同步飞书评论”分别操作，自动保存和切换项目不会自动上传正文。发布成功后保留本地原稿，并分别保存发布前 `local.xml`、评论 JSON 和实际回读 `cloud.xml`；相邻反馈记录双方基线与备份位置。即使差异只是云块 ID，也不自动覆盖本地。再次预览可核对并明确确认采用回读，才下载云资源并更新原文件；关闭预览会继续保留原稿。

“项目管理”只显示“项目配置路径”和“修改”按钮。编辑目录后点“保存”才切换，服务合并项目登记；冲突时保留输入与原配置。默认目录为 `~/.lark-review/`，旧实例显示实际使用的位置。正文、评论和资源仍在文章旁，浏览器只记住最近项目。该索引可供后续插件或客户端复用，当前尚未集成这些客户端。

创建组合、目录规则、索引格式与失败恢复见 [项目与同步指南](../projects-and-sync.md)。

## 使用

正文可以直接编辑，常用格式提供小工具栏。编辑、只读两种模式都能选择正文并添加评论；可回复和解决评论。添加评论后自动保存，不需要导出或复制反馈。

顶部路径栏显示当前选中文件的完整路径，可复制；左侧文件栏列出 XML 和相邻反馈 JSON，点击文件即可查看对应路径。“项目管理”显示当前实际使用的项目配置目录。读完直接告诉 AI：“我在这份文章里留了意见，请读 XML 和旁边的 review.json。”

文件栏展开与收起共用顶栏左上角同一个按钮，位置和大小不变，只切换图标与提示；目录展开、滚动位置和按钮焦点会保留。项目选择列表向下展开，显示项目名、本地路径和当前项目标记，长列表可以滚动。

左侧资源树集中显示当前正文、相邻反馈和 XML/资源记录明确引用的本地文件，按目录展开；不会扫描整个工作目录。点击正文回到编辑器，反馈 JSON、图片与受支持的文本资源可只读查看。TXT、CSV、SVG、PlantUML 等文本以源码显示，HTML 与代码不会执行；资源文件暂不在页面内修改。

文件在外部修改后，页面空闲时自动更新。正在输入的正文、评论或公式草稿会阻止自动载入；多个浏览器同时保存会校验两份文件的版本，发生冲突时保留本页输入。重新载入磁盘版本需要你明确选择放弃本页未保存内容，外部新版本也会清除旧的撤销历史。

## 当前格式范围

- 可编辑：标题、段落、加粗/斜体/下划线/删除线、颜色、行内代码、代码块、链接、引用、多级列表、复选框、简单高亮块、表格及合并单元格正文，以及分栏内的正文。
- 公式用 KaTeX 呈现；在编辑模式选中已有公式，可在侧栏修改表达式并点击“应用公式”。暂不提供新建公式入口或图形化公式编辑器，无法渲染的表达式会保留并显示源码。
- 已呈现自动标题编号、表格 `colgroup` 列宽、代码 `caption/lang`、官方回读代码的 `br` 换行、六位小数分栏比例，以及图片尺寸、`scale` 和说明。已支持回读的 RGB/RGBA 色值；命名色按文字、背景、表格、高亮块和边框分别映射，当前 24 项有同源回读证据；尚未验证的命名色保留原值，不套用近似色。Go、JavaScript 代码已有语法高亮和行号，支持常见语言别名；未知语言保持普通代码。高亮、行号和标题不写入正文或评论位置，代码区域关闭拼写检查；部分属性尚无工具栏设置入口。
- 本地图片通过限定目录的文件服务预览。已下载的 token 图片可通过旁置 JSON 的 `resources` 映射到本地原图；保留 XML 中的原引用，不自动联网获取。
- 内联 Mermaid、SVG 白板支持本地预览。编辑模式选中带内联图源的白板，可在侧栏改源码，预览成功后“应用白板”，沿正常正文事务自动保存并支持撤销、保留整体评论；SVG 保存为真实子元素。这不是拖拽图内节点的画布编辑器。空白白板显示画布；`src/token/path` 可精确映射已下载的栅格或 SVG 静态预览，SVG 清理活动内容后保留服务端 viewBox。暂不在本地渲染 PlantUML 源，也不自动展开文件图源；可通过已下载预览显示图形，资源树点击图源或 SVG 缓存则只读源码。没有本地映射的引用显示未缓存。
- 附件原 XML 保留：行内附件显示文件名，Card 显示名称、类型与大小；Preview 及独立 `source` 可预览文章目录中的栅格原图。云附件通过 `resources` 的 `source + token` 精确关联下载文件，不借用图片 token、不自动下载。PDF、HTML 及复杂未知附件结构不执行或展开。
- 电子表格、云动态块及其他未知结构保留原 XML，以名称或占位展示。
- 无改动往返保留原 XML 字节；修改可编辑块时保留未知块与原属性。行内附件的后文有专项回归。
- 评论支持文字选区，也支持公式、图片、白板、附件等原子节点的整体高亮与定位。附件评论保留可读的文件名；编辑事务会迁移评论范围，删除引用后保留评论并标记“已删除”。外部整篇改稿后，旧评论位置标为待确认，避免字符串重复时误挂。

[综合测试稿](../../examples/compatibility.xml) 以 S00–S13 编号覆盖格式与协作行为；[本地资源测试稿](../../examples/local-resources.xml) 以 S14 覆盖图片、行内附件、Card、Preview、同名不同内容附件及 CSV。两份样稿使用真实本地素材，不含伪造资源 token。默认欢迎稿来自 `examples/demo.xml`，其中附件和白板仍是示意 token，只用于原文保留测试；不能拿这些示意资源发布到飞书。已有 `.local/welcome.xml` 不会因样稿更新而被覆盖。

[白板图源样例](../../examples/whiteboards.xml) 以 S15 覆盖 Mermaid、SVG、PlantUML 和 blank，SVG/PlantUML 使用真实本地文件；CLI 发布前负责展开文件图源。[Sheets 样例](../../examples/sheet-roundtrip.md) 提供 6×5 官方单元格输入、单格修改与恢复、预期值映射；它目前用于离线校验，不代表页面已有电子表格内部编辑器。

## AI 接入和发布边界

见 [本地协议](../protocol.md)。无需 MCP 或额外 AI SDK；`baselineXML` 和当前 XML 可用于对比人工改动。反馈 JSON 是本项目的本地协议，不是飞书云端评论导入格式。

飞书交换使用官方 CLI 的文档命令。例如，对已备齐资源的实际文章，官方入口为 `lark-cli docs +create --doc-format xml --content @./article.xml`。其他实现需适配相同命令与回执；执行前须核对实际资源路径、当前 CLI 能力和资源权限。

官方发布版 **v1.0.95 已在 Apple Silicon Mac 实测**：页面建文档、正文双向同步、图片/卡片附件/白板预览，以及评论、回复、解决和恢复均完成真实往返；官方该版本仍有行内附件尾文丢失问题。命令接口兼容不代表版本能力完全相同，范围与证据见 [官方 CLI Mac 验收](official-cli-mac-2026-09-13.md)。

验收要求把**本地视觉、本地文件、飞书文件**连在同一条链上：同一份 XML 与资源经官方协议写入 → `full fetch` 保存完整响应、正文、`reference_map`（若返回）与资源 → 本地重新打开并检查视觉 → 本地修改落盘并按官方协议更新 → 再次完整回读核对。独立 HTML 粘贴样例或 DOM 测试不能代替这个闭环。

## 白板组件评论

Demo 现有真实 SVG 与 Mermaid 流程图。点击其中节点，然后选择“评论选中组件”；评论自动保存在相邻 JSON，点击评论引用可回到该节点。云端下载的 SVG 预览保留真实节点 ID，也可以本地评论组件。没有节点结构的图片预览仍只能评论整块。

本地尚未提供拖拽原生白板。关联文件后可通过“同步飞书评论”按钮交换评论、回复和解决状态。兼容 CLI 现已支持官方兼容的评论创建、回复、解决和恢复；创建定位到文档或 Docx 块，不能假称支持创建画板内部锚点。详见 [协议](../protocol.md) 与 [本轮实测](whiteboard-comments-2026-09-12.md)。

## 飞书评论同步

默认完全本地。需要交换评论时，准备带真实块 ID 的飞书导出 XML，在本机创建关联配置，例如：

```json
{
  "command": "lark-cli",
  "args": ["--as", "bot"],
  "documentId": "实际Docx文档ID",
  "url": "https://你的域名.feishu.cn/docx/实际Docx文档ID"
}
```

用 `npm start -- --file /absolute/path/article.xml --cloud-config /absolute/path/cloud.json` 启动。配置会关联启动文件的项目；若已有项目绑定不同文档，启动会拒绝冲突。多项目也可使用上方 `--cli-config`，在新建项目时关联飞书来源。页面评论区出现“同步飞书评论”和目标链接；启动、打开文章和自动保存都不会向飞书发送内容。CLI 需要事先配置好身份与评论权限；阅稿器不会发起登录。替代 CLI 的可执行文件与参数在本机连接配置中指定，须满足同一官方命令约定；项目没有运行时跨仓依赖。

点一次按钮会先保存本地，再拉取完整评论/回复，推送新增本地意见与回复，并同步解决/重新打开状态。白板意见发布到整个 Docx 白板块，组件名称写在评论内容里；云端原生组件意见导入为整图评论，保留原引用。正文和资源不会随评论上传。

评论 ID、回执和同步记录仍在文章旁的 `.review.json`。重复同步按 ID 去重。找不到对应块时保留本地意见；超时且无法确认是否发送成功时，保留 `cloudSync.pending` 并暂停后续发送。先核对回执，不能直接删记录重试。全文评论和仍处于已解决状态的评论不接受云端回复，新增回复会留在本地并说明原因。已同步的评论正文改写不会自动覆盖原云线程。

具体协议与恢复规则见 [本地协议](../protocol.md)。
