# VS Code 只读版 0.1.0 验收

2026-11-17，macOS 上的本机 VS Code。所有用例使用仓库公开素材或临时合成文件，没有连接飞书或读取业务原稿。此记录区分自动测试、真实宿主和原生界面观察。

## 自动检查

- 根项目：`npm run typecheck`、`npm test`（65 文件、821 项）、`npm run build` 通过。依赖修复后再跑全量，除需更新预期的 5 项归因测试外，816 项通过；归因更新后单独复跑 5 项全部通过。HTTP 用例需要 loopback 监听，在允许本地端口的环境运行；首次沙箱运行的端口拒绝不算功能失败。
- Obsidian：类型检查、构建及 93 项测试通过，覆盖抽出的共享 DocxXML 识别函数。
- VS Code：类型检查、17 项测试、构建和 VSIX 打包通过。覆盖文件关联、格式识别、资源路径和链接限制、坏评论回退、只读渲染、合并表格、公式、SVG 清理、源码桥接与外部变更刷新。
- `node scripts/generate-third-party-notices.mjs --check --verify-bundle` 通过，含新 VS Code 宿主与 Webview 入口。

## 分发依赖

复用的旧锁文件命中运行时安全公告，已在兼容版本范围内更新 DOMPurify 3.4.18、Mermaid 12.3.0、lodash-es 4.18.1 及相关依赖。`npm audit --omit=dev` 回读为 0；这不是所有开发工具依赖均无告警的声明。新版 ELK 的版权与内嵌 Worker 适配归因重新核对，原始通知及 Apache 全文随包保留。

## 真实扩展宿主

隔离用户目录中加载插件与专用测试驱动，使用 VS Code API 检查：普通 `ordinary.xml` 打开为 `TabInputText`；旧 DocxXML 执行预览命令后为 `feishuDoc.legacyReader`；`.feishu.xml` 默认选择 `feishuDoc.reader`，标签无 dirty 状态。驱动与原始回执留本机临时目录，不打入 VSIX。

## 已安装 VSIX 的界面

在正常 VS Code 的新测试窗口安装并打开公开合成样稿，受限模式保持开启。原生界面观察确认正文、目录、合并表格、公式、PNG、SVG 白板和已有评论、回复显示；刷新与源码按钮带有帮助提示。

单独打开文件而未打开文件夹时，最初的递归监听未收到外部变更。改为文档及已引用资源所在目录的非递归监听，并且非 dirty 文本缓存不覆盖磁盘读取。重新安装后，在新窗口修改磁盘 XML 与相邻评论 JSON；未点击刷新，界面正文和评论均更新为对应新内容。这个边界另有模拟宿主回归测试。

实际点击「查看源码」进入原生 XML 文本编辑器，再点击编辑器标题的预览按钮返回只读视图。阅读器没有保存、另存、撤销写回或创建评论的实现，查看源码后的手动编辑属于 VS Code 原生行为。

## 范围

没有验证 SSH 远程、Windows、Linux、多平台媒体解码或飞书往返；此版也没有云同步、富文本编辑和新增评论能力。资源与未知块沿用共享渲染器的支持范围。桌面截图含宿主窗口信息，原始证据不作为公开产品素材分发。
