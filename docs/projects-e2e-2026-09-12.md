# 多项目与正文同步验收 · 2026-09-12

本次使用独立本地文件、项目索引和专用飞书测试稿。主样稿的本地 XML 与反馈文件在测试前记录哈希；云端主样稿只读导入，不用它验证覆盖发布。私有回执、截图和真实文档身份保存在本机 `.local/projects-e2e-20260912/`，不进入公开仓库。

## 已执行的真实链路

| 场景 | 操作与结果 |
| --- | --- |
| 新建本地及云端项目 | 浏览器填写新文件、新飞书文档与默认方向；返回实际云文档，登记项目并建立旁置 JSON |

| 飞书 → 本地 | CLI 向同一专用稿追加另一段文字；页面预览并确认拉取，原段落保留，新段落可见，三份正文一致 |
| 重复同步 | 再次打开预览显示“两端没有待同步的内容”，没有确认写入入口 |
| 已有飞书 → 新本地项目 | 从主样稿的真实版本创建独立副本，完整 XML 与 18 份引用资源落盘；主样稿未被写入 |

| 项目隔离 | 下拉框在独立测试稿与样式副本间切换，路径、正文、评论和云目标随项目切换 |
| 共享目录 | 浏览器指定独立目录并开启共享，管理文件切换到该目录；关闭后保留共享文件并合并回实例索引，两份登记一致 |
| 三方显示 | 对照本地页面、磁盘 XML/资源与 Chrome 飞书页面的表格等内容；据此修正本地表头默认居中问题。截图窗口尺寸不同，未声称像素级一致 |

## 自动化覆盖

测试覆盖真实文件读写和 HTTP 接口，也覆盖界面状态；模拟 CLI 用于可控地验证故障、并发与部分成功，不能代替上面的真实云端往返。

多项目与同步阶段的 `typecheck`、构建及 40 个测试文件中的 443 项用例通过。后续布局调整与 456 项完整回归见[工作区布局验收](layout-review-2026-09-12.md)。HTTP 用例首次被沙箱的 loopback 监听限制阻止，允许本地监听后完整重跑通过。配套兼容 CLI 的 Go 全量测试及构建通过；旧 Go 工具链在本机需要外部链接器运行测试，保留了对应日志。

- 项目登记与唯一性：同文件重复、Wiki/Docx 实际身份重复、非法路径、旁置文件冲突、特殊文件拒绝、已有稿不被“新建”覆盖。
- 切换与草稿：先保存后切换，未发送评论阻止项目切换；回复和公式草稿阻止评论同步，公式与白板草稿有切换只读、卸载和外部载入保护。创建期间表单禁用，迟到响应不覆盖新输入。
- 同步计划与并发：只读预览，单次确认，过期预览、本地/云端版本或原始资源变化拒绝写入，正文与评论共享同步锁。
- 写入与回读：按块替换、追加和需要整篇替换的提醒；真实 ID 回填，格式不等价时保留本地稿；超时及部分成功保留 pending 与私有回执。
- 素材：相对路径与 `@` 路径、图片/附件下载、白板 token 不变时刷新缓存、同路径素材内容变化检测、越界与重复下载目标拒绝。
- 共享索引：默认关闭、自定义目录、开启/关闭/更换目录、冲突合并、重启恢复，以及设置切换与正文/评论操作的实际 HTTP 竞争。
- 浏览器缓存：仅保存目录偏好及最近项目 ID；恢复依赖服务端有效登记，缓存失效或被禁用不删除项目和正文。
- 权限提示：文档创建与管理员权限结果分别处理，失败提示不泄露原始回执或账号标识。

## 实际发现并修复的问题

新建含图片的文档曾在云端创建后停止上传。真实 DocsAI 创建回执带有效文档 ID、URL 和版本，但没有 `result` 字段；兼容 CLI 原先把它判为不完整。修复仅放宽可核验的创建回执，更新操作仍要求明确成功；同步和异步创建均补资源上传次数测试。

另外修复了创建输入中的 `@` 资源路径、重复标题、原始回执丢失、创建后资源变化检查、共享设置与正文操作的竞争，以及 PlantUML 图源已有云端预览却未显示的问题。权限失败保留已创建文档，不把重新创建当作恢复方式。

本次专用测试应用取得协作者列表读取权限后，真实列表接口回读成功。对四篇已知身份的专用测试稿分别执行一次邮箱授权；接口确认写入，回读列表出现具有管理权限的 Open ID。浏览器还核对了其中一篇的目标用户显示“可管理”。这些操作未重建文档。

真实接口暴露了另一处差异：授权响应回显邮箱，而协作者列表返回 Open ID。CLI 现在分别保存写入确认与身份回读结果；没有精确身份映射时返回 `identity_unresolved`，不把写入成功当成完整核验，也不据此重复授权。本次未启用邮箱查询用户 ID 所需的权限，因此没有完成默认管理员的全自动身份核验；这是该次验收的限制，不代表其他部署的权限状态。

## 边界

共享目录是同机可访问目录中的项目登记，当前没有跨电脑同步或插件集成。正文同步必须预览后确认；评论同步仍是独立入口。公开评论接口不能完整交换白板内部节点定位，云端按整图评论，本地保留组件引用。

本地 XML、CLI 与飞书之间没有跨系统原子事务。云写入可能部分成功，当前保留 pending、快照与回执供核对，还没有自动恢复按钮。未知块保留原 XML；电子表格和原生白板内部编辑并未因此变成完整飞书客户端。
